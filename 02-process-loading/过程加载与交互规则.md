# AI 回答过程与交互规则

版本：2026-09-18。适用于过程加载原型及后续前端接入。页面目前使用模拟事件，不连接真实模型或执行真实工具。

## 1. 三个示例入口

| 示例问题 | 演示内容 | 结束方式 |
| --- | --- | --- |
| 审查一下船舶设计论文的目录 | 常规资料审查 | 收起过程并输出回答 |
| 初始化工作空间并核对资料，生成完整方案 | 复杂成功流程：多阶段进度、工具调用、并行任务、校验与产物整理 | 全部成功后收起过程，流式输出正文 |
| 生成完整审查建议（模拟模型报错） | 动态异常流程：读取完成，校验执行中触发超时 | 收起历史，外层持续显示失败提醒 |

第二个示例不包含超时、中断、失败重试或子任务部分完成。第三个示例在正常速度下约 4 秒超时，受播放速度设置影响，不代表正式产品超时阈值。

第一个示例当前仍复用常规审查脚本，包含可恢复的远程查询失败和重试；它是相对简单的流程，并非只有少量步骤的极简版本。

## 2. 消息布局

单轮消息从上到下为：

1. 用户问题。
2. 过程总状态与耗时。
3. 可展开、收起的过程历史。
4. 位于历史折叠容器之外的异常提醒。
5. 回答正文。
6. 底部操作图标与结束时间。

耗时表示本轮持续多久；底部时间表示本轮何时结束。异常摘要不能藏在需要展开的历史中。

## 3. 状态与转换

| 状态 | 展示及行为 |
| --- | --- |
| 正在处理 | 展开过程，显示当前动作、阶段说明及加载状态 |
| 正在回答 | 过程自动收起，正文从开头流式输出 |
| 已完成 | 停止加载，显示回答操作与结束时间，历史可回看 |
| 超时或错误中断 | 停止后续生成、记录结束时刻、自动收起历史，异常卡常驻外层 |
| 用户停止 | 停止后续事件，保留已有正文与历史，恢复发送能力 |
| 等待确认 | 明确显示确认说明，等待用户操作，不视为成功或已结束 |

原型将超时及错误终止映射到轮次 `stopped`，通过事件 `terminal` 区分具体原因。过程标题因此显示“已停止”，异常卡说明“模型响应超时”等具体原因。正式接入独立 failed、timeout、confirm 状态时，需同步输入区、侧边栏和操作行逻辑。

## 4. 过程编组

- 保留完整事件与原始顺序，收起仅改变展示。
- 助手进度文字独立显示；文本、异常、确认及轮次结束形成分组边界。
- 两条以上连续普通事件进入操作组；单条直接展示，不额外套组。
- 读取、检索、能力加载、命令执行、编辑、等待、思考摘要、上下文整理、子任务与产物生成均可归入普通操作组。
- 运行中的组优先显示最新具体动作。组完成后显示语义摘要和操作数量。
- 摘要优先取 `actionSummary`，其次按操作类别判断，无法判断时使用“已完成 N 项操作”。正式接入必须只统计真正完成的操作。
- 每个事件、操作组和子任务有稳定标识。点击只改变当前节点，后续更新不能重置其他节点的展开状态。

深度思考只展示面向用户的阶段摘要，不暴露模型内部推理。长内容提供“展开全部”，重绘时不重复入场动画。

子任务可在操作组内逐层展开。标题、状态与箭头保持同一行；完成后默认收起。子任务异常影响结果时，额外展示外层摘要。

## 5. 异常提醒与自动收起

阻断整轮生成的超时或错误发生时：

1. 停止追加运行事件和正文，停止加载及计时。
2. 记录本轮结束时间。
3. 自动收起过程历史，保留手动回看入口。
4. 同时显示外层异常卡，不等待折叠动画结束才告知用户。
5. 卡片下方显示重新生成图标和时间。

异常卡不参与过程折叠。自动收起、手动收起和重新渲染均不能隐藏该提醒。

第三个示例标题为“模型响应超时”，说明为“模型未在限定时间内完成回答，本次生成已中断。已完成的过程仍会保留。”底部不重复显示“已保留执行记录”。

可恢复的工具失败与终止整轮的异常需区分；恢复中的轮次不记录结束时间。等待确认同样不是终态。原型依据 terminal 元数据与 stopped 状态识别常驻提醒，完整确认及恢复协议尚待接入。

## 6. 底部操作与时间

| 情况 | 底部内容 |
| --- | --- |
| 有正文且生成结束 | 复制内容、复制 Markdown、结束时间 |
| 无正文的异常中断 | 重新生成、结束时间 |
| 正在处理或输出 | 不显示结束操作行 |

- 复制内容使用双页轮廓图标，Markdown 使用方框 M 图标，两者均为 16 × 16px。
- 点击区域保持 28 × 28px，不随图标缩小。
- 重新生成使用环形箭头，当前图形为 20 × 20px；不显示按钮文字，悬停提示和无障碍名称为“重新生成”。
- 时间使用文字，不使用时钟图标。格式为“M月D日 HH:mm”，例如“9月18日 11:37”，小时、分钟补零。
- 时间采用浏览器本地时区，字号 14px，弱化灰色，与操作图标居中对齐。
- 结束时刻固定，展开、收起、切换会话和重绘不能改变它。新一轮生成使用新的时间。
- 使用 `time` 元素，`datetime` 保存 ISO 时间。正式服务应提供持久化的结束时间。

当前正文是纯文本，两个复制按钮复制同一份内容。无正文的重试按钮进入常规生成流程，不保证再次模拟超时。存在部分正文的停止状态目前显示复制操作行，尚未增加同时重试入口。

## 7. 滚动和动效

- 处理阶段默认跟随新事件；过程列表达到高度上限后内部滚动。
- 用户向上浏览或操作过程节点后暂停跟随，后续更新不强制拉到底部。
- 用户主动返回底部或点击跳转提示后恢复处理阶段跟随。
- 内层列表到达边界后，滚轮传递给对话页面。
- 正文阶段不自动追底，用户从开头阅读。
- 下方有内容时，输入框上方出现圆形跳转提示：运行中为三个动态圆点，结束后为向下箭头。
- 过程折叠沿用约 200ms 的过渡，异常卡不参与折叠。
- 高频更新不反复播放已有卡片入场动画，遵守系统减少动态效果偏好。

## 8. 正式事件接入要求

服务端至少提供轮次 ID、事件 ID、类型、状态、发生时间、动作摘要及可选详情。终止事件还需提供用户可读原因、错误类型、是否可重试和结束时间；子任务提供各自状态。

- 按稳定 ID 追加或更新节点，保留真实顺序。
- 明确推送终态，不依赖长时间无消息猜测失败。
- 正常结束、中断、超时均只写入一次结束时间。
- 停止后忽略旧轮次的迟到事件，重试开启新轮次。
- 未知工具使用中性标题，不凭名称推断成功。
- 事件更新不能清空用户的阅读和展开状态。

## 10. 验收与当前边界

- 首页三条入口分别可用，异常入口先运行再超时。
- 复杂流程无终止异常，完整输出成功回答。
- 超时后历史收起，提醒常驻，加载停止，重试入口可用。
- 历史可回看，展开过程不影响异常可见性。
- 正常和异常结束均显示固定日期时间，运行中不提前显示。
- 复制图标为 16px，重新生成只显示图标，不出现“已保留执行记录”。
- 阅读历史不抢滚动位置，正文从开头阅读。
- 键盘操作、图标名称和减少动态效果模式可用。

尚待正式接入：独立 failed/timeout 状态、确认动作、部分正文重试、中断时操作组成功数量的准确统计。这些属于目标规则，不能视为原型已完整实现的后端能力。
